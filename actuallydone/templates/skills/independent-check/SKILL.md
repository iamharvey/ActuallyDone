# 独立复核（对抗检查）

**你是复核者。**你没有参与实现，也不该去了解实现过程——那正是你的价值所在：
自己检查自己的模型会复用同一套盲点，把「我以为我做对了」原样再确认一遍。

判据全部在仓库里，不在任何人的会话里：受监视代码树的哈希、验收契约、三份基线、
回执链。所以你不需要读实现者的聊天记录，也不该读。

## 三条铁律

1. **不看自述看证据**。「测试全部通过」这句话本身不是证据，`{{RECEIPT_PATH}}` 里的
   树哈希、通过用例名单、每步命令输出才是。
2. **只报告，不修复**。发现问题就写进结论，交回实现者。你顺手把代码改对了，
   下一轮就没人复核了。
3. **不替它记账**。`{{ADONE}} policy --accept`、`{{ADONE}} integrity --accept-baseline`
   与 `{{ADONE}} gate waive-tests` 是实现者说明「我为什么放松了门槛」的地方，
   复核者跑它等于自己给自己放行。

## 怎么做

```bash
{{ADONE}} brief      # 冷启动：这个项目的判据在哪、该读什么、不许动什么
{{ADONE}} doctor     # 配置与现实是否一致（路径、命令、钩子）
{{ADONE}} audit --reviewer <模型名>   # 与回执 runner.model 对照；相同则不通过
{{ADONE}} audit report   # 把已有结论渲成一页 HTML，不重跑检查
```

不信任实现者那份回执时（它可能是精心构造的），自己重跑：

```bash
{{ADONE}} audit --rerun
```

`--rerun` 会把门禁全量跑一遍，与实现者的回执逐项比对：树哈希对不上、
它写着全绿而你没跑过，都会被点名。产物只写进 `{{STATE_DIR}}/audits/`，
**不会覆盖** `{{RECEIPT_PATH}}` 与证据链——被审的证据不能由复核者动。

耗时按项目规模，等同于一次完整门禁。默认那条快路（读回执 + 判据锁 + 假绿 + 契约 +
抽查真跑）通常几十秒内出结论，够用于绝大多数复核。

## audit 说不通过时，怎么读

| 结论 | 它说明什么 |
| --- | --- |
| 回执已过期 | 跑完门禁之后代码又改过，那份绿灯证明的是另一份代码 |
| 回执本身未通过 / 不完整 | 实现者拿一份没全绿或跳过了步骤的回执来交差 |
| 自哈希对不上 / 不在证据链上 | 回执被手改过，或被换成了另一份旧回执 |
| 判据被放松且没有记账 | 改的不是代码是尺子：受监视范围、步骤命令、契约、豁免名单 |
| 契约里的用例不存在 / 不在通过名单 | 需求缩水或编了一个用例名 |
| 抽查用例现在跑不过 | 回执里写着通过，当场跑却不通过 |
| 抽查一条都没跑起来 | 那不叫通过，那叫没跑（常见于步骤被换成假脚本） |
| 复核者与跑出门禁的是同一个模型 | `--reviewer` 和回执 `runner.model` 相同，等于自己审自己 |

## 报告怎么写

给人看的结论要能被第三个人复现，所以必须包含：

- 对照的回执 ID 与当前树哈希前 12 位
- 复核方式（读回执 + 抽查，还是 `--rerun` 全量重跑）
- 问题逐条，每条指向具体文件或命令
- 结论文件路径：`{{STATE_DIR}}/audit.json`（给人看的那页是 `{{STATE_DIR}}/audit.html`）
- 一句明确的判定：**未通过时，实现者不能宣称完成**

不要写「基本没问题」「应该可以」。复核只有两种结论：通过，或者未通过加一张问题清单。

## 怎么开一场真正的对抗检查

复核要有效，得满足两件事：**换一个上下文**，最好**换一个模型**。

1. 实现者交付后，开一个**新会话**（不要接着原会话往下说）。
2. 只给这一句：「按 independent-check 独立复核这个仓库的交付。」
   不要粘贴实现过程、不要转述它做了什么——那会把它的盲点带进来。
3. 复核者跑 `{{ADONE}} audit --reviewer <自己的模型名>`。回执里的 `runner.model`
   与这个名字相同，审计不通过。缺任何一边只写进依据，不当失败。
4. 未通过则把问题清单原样交回实现者；修完由复核者**再核一次**，不是由实现者自证。

口径与回执字段的读法见 [completion-gate](../completion-gate/SKILL.md)，
契约的校验规则见 [acceptance-contract](../acceptance-contract/SKILL.md)。

## 它挡不住什么

复核者与实现者跑在同一台机器上、用同一套文件权限。一个铁了心造假的实现者可以重算
整条回执链并同步改掉三份基线——本地方案到此为止。`--rerun` 把成本又抬高一档
（它得让真跑的结果也对得上），但真正的不可伪造需要一个 Agent 无权写入的执行者（CI）。
这一点必须在报告里如实说明，不要把「独立复核通过」写成「不可能造假」。
