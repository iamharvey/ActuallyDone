# 调外部接口要真的发请求

照着接口文档返回期望值，用例是绿的，功能是假的。门禁只看用例，挡不住这种假实现，只能靠写法挡。

## 实现

- 用真实的 HTTP 客户端或 SDK，按文档拼请求（方法、路径、参数、请求头、请求体），解析真实返回。
- 地址、凭证从配置或环境变量读，不写死。
- 不要把文档里的示例响应写成返回值、常量或兜底分支。请求失败就报错或按需求降级，不要「失败时返回示例值」。
- 生产代码里不要判断「是不是测试」再返回固定值。

## 测试

- 假数据只放在测试里：注入假的传输层，或在用例里起一个本地假服务，把地址指过去。
- 断言请求真的发出去了：方法、路径、关键参数和请求体都要核。
- 换一个响应值再断言一次，结果必须跟着变。只断言「返回值等于文档示例」的用例，写死返回值也能通过。
- 用例不连外网。

## 联调不了时

没有凭证、沙箱或网络时，照样写真实调用，用假服务测通，交付时写明「未与真实接口联调」和缺什么。
文档不够写出真实调用时（缺地址、缺字段含义、缺鉴权方式），说缺什么，不要编。
