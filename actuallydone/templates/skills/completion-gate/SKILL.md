# 完成门禁

**完成 = 存在一份回执，它的树哈希等于当前代码的树哈希，且每一步都通过。**

不是「我跑过测试了」，不是「日志贴在上面」，不是勾了清单。这些都由被检者自己撰写，
挡不住四种伪完成：贴过期日志、转述而不真跑、**跑完门禁再改代码**、编一个不存在的用例名。

## 怎么用

```bash
{{ADONE}} gate run --changed   # 开发中：只跑与 dirty / 本次改动相关的用例，不写 latest.json
{{ADONE}} gate run             # 交给另一个模型之前：全量门禁并写回执
{{ADONE}} gate run --affected  # 只跑相对上一份全量绿回执变过的模块（Maven），其余继承
{{ADONE}} gate check           # 校验全量回执是否新鲜且全绿，约 1 秒
{{ADONE}} gate slow            # 读最近一轮 surefire 报告，列出最慢的用例
```

开发中改了受监视文件，只跑 `--changed`。**不要**在问答或改完一个文件之后跑全量 `gate run`。
问答且未改受监视文件时，stop 钩子不应出现；如果出现了，先看 dirty 是不是上一轮留下的。

全量回执（`latest.json`）是交给另一个模型的证据，不是完成声明。`--changed` 写的是 `.adone/partial.json`，不能当这份证据。

`{{ADONE}} gate check` 通过之后，换一个模型，按 independent-check 跑
`{{ADONE}} audit --reviewer <模型名>`。交给对方时引用回执 ID（形如 `20260810-213012`）
与树哈希前 12 位，以及全部用例通过{{COVERAGE_CLAIM}}。不要复述测试日志，也不要说「可以完成了」。

门禁只回答「这次改动是否全绿」。要看整个项目的健康度（技能沉淀、代码质量、需求台账、AI 物料），
跑 `{{ADONE}} health`——它默认读这份回执而不重跑测试，`--all` 才会重跑门禁。

## 回执里有什么

`{{RECEIPT_PATH}}`，由脚本写，不要手改：

- `tree.hash` / `tree.file_count`：受监视代码树（{{WATCH_DESC}}）的内容哈希。
  **改一个字符哈希就变**，这是「跑完再改」被抓住的原因。
- `tree.impl_changed` / `tree.tests_changed`：相对上一份全量回执，实现变了而测试文件没变。
  这不是完成证据。没有新行为时由人在终端跑 `{{ADONE}} gate waive-tests "理由"`，不要自己销账。
- `tests.passed_names`：通过用例名全集。验收契约靠它证明「这条需求真有用例跑过」。
- `steps`：{{GATE_STEPS}}，每步的命令、退出码、输出尾巴。
- `coverage.percent`：{{COVERAGE_DESC}}

## check 说不通过时

按提示逐条处理，**不要绕过**。常见几种：

- **「回执已过期」**：你在跑完门禁之后改了代码。重跑 `{{ADONE}} gate run`。这是最常见的一种，
  也是最该老实重跑的一种——哪怕只改了一行注释，也没人能替你保证它无害。
- **「实现变了，测试文件没有变」**：补一条对着新行为的用例再跑全量。确实没有新行为时，
  由人执行 `{{ADONE}} gate waive-tests "理由"`。不要自己跑这条命令。
- **「有用例被条件跳过」**：整批用例因为连不上依赖（数据库、外部服务）被跳过了，
  这种「绿」什么也不证明。把依赖起起来重跑。
- **「用例 X 没有出现在回执的通过名单里」**：契约绑的用例没跑过或没通过，见
  [acceptance-contract](../acceptance-contract/SKILL.md)。
- **「N 个用例消失了 / 跳过涨了」**：假绿检测报的，见
  [test-integrity](../test-integrity/SKILL.md)。
- **「判据被放松且没有记账」**：你改的不是代码，是尺子——缩了受监视范围、换了步骤命令、
  删了检查项或验收契约、把用例名加进了豁免名单。改判据本身不是错，不说一声才是。
  确属合理时 `{{ADONE}} policy --accept "为什么"` 记一笔再继续；不是有意为之就改回去。
- **「回执的自哈希对不上 / 与证据链头对不上」**：`{{RECEIPT_PATH}}` 被手改过，或者
  被换成了另一份旧回执。回执只能由 `{{ADONE}} gate run` 产出，重跑一次。

跑不了门禁时（本机缺依赖、装不上包），**直接说卡在哪一步、看到什么输出**，让人来判断。
谎报一句「已完成」的代价，比说一句「跑不了」大得多。能做的部分照样做完，不要因为门禁跑不了就停下。

## 有用例失败，但不是这次改的

别人留下的失败用例不是你停工的理由。先拿证据判归属，判不清就按你改坏的处理：它在 `{{RECEIPT_PATH}}`
的 `tests.failed_names` 里已经失败，或者用 `git worktree add` 在 `HEAD` 上单跑也失败（不要 `git stash`）。
只看 `git diff --name-only` 不够，你的改动可能弄坏别的文件里的用例。确认无关之后：

- **不要停下**，把本轮的任务做完，本轮改动的相关用例要通过。
- 不修它，不跳过、不删、不改弱断言、不加豁免。它不在这次的范围里，动它就是降标准。
- 照实交付：「全量门禁未通过，原因是既有失败 `<用例名>`，证据是 …；本轮相关用例通过」。
  这不是完成。先修它还是另开任务、提交被钩子拦住怎么办，由人决定。

## 调外部接口要真的发请求

实现里用真实的 HTTP 客户端或 SDK 发请求。不要把文档里的示例响应写成返回值、常量或兜底分支。
假数据只放在测试里，用例断言请求本身；联调不了就照实说。细则见 [references/external-api.md](references/external-api.md)。

## stop 与提交

{{HOOKS_NOTE}}

stop 的 `status=completed` 只表示「这轮说完了」，不是用户说「做完了」。
本轮没改受监视文件时钩子静默放行，即使全量回执过期或还没有回执。
改了受监视文件时只要求相关用例通过；回推里出现的命令必须是 `gate run --changed`，禁止去跑全量。

## 判据变更要记账

「让门禁变绿」有两条路：把代码改对，或者把尺子改短。后者包括缩小 `gate.watch_roots`、
把测试命令换成只跑一条、删掉一份验收契约、把用例名塞进 `tests.baseline_exempt`。
这些都会被判据锁比对出来：

```bash
{{ADONE}} policy                                   # 有没有人把门槛悄悄调低
{{ADONE}} policy --accept "为什么这次要放松，理由写清楚"
```

判据基线、假绿基线、证据链头三份都建议入库——它们是证据，不是缓存，入库之后
每一次放松都会出现在 diff 里。

## 交付时把结论交给别人验

你自己跑 `gate check` 证明的是「证据自洽」，而你正是被检者。真正的复核由一个**没参与实现**
的执行者做：开一个新会话（换个模型更好），让它按
[independent-check](../independent-check/SKILL.md) 跑 `{{ADONE}} audit`。

你这边要做的只有一件事：**把证据留全**（回执是 `gate run` 产的、判据放松已经 `policy --accept`
记过账、契约条目绑的是真用例名），然后交出回执 ID 与树哈希——**不要转述你的实现思路**，
复核者不该看你的推理过程。它跑出的结论落在 `{{STATE_DIR}}/audit.json`，不会覆盖你的回执。

这套机制提高伪造成本，不是密码学级不可伪造，边界见 [references/limits.md](references/limits.md)。
